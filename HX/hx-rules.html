  • 檔案：倉根目錄 HANDOVER.md（唔喺 HX/ 入面）。
  • 位置：GitHub 私人可見嘅公開倉 danson117/danson117.github.io。兩部機都要 git pull 先睇到最新。

幾時讀／幾時寫

  • 做任何嘢之前：先讀 HANDOVER.md。另一部機有新紀錄而呢部未跟上 → 先對齊（pull GitHub；Supabase／Vercel 跟日誌），再做下一步。唔好靠估。唔好用舊本機檔覆蓋。
  • 做完每一次改動之後：同一輪將重點寫入 HANDOVER.md（日期、邊部電腦、做咗乜、喺邊：GitHub／Supabase／Vercel），然後 commit + push。屋企／公司隨時可能換機繼續，另一部機要知做過乜，先唔會脫節。
  • 公開日誌唔寫職員訓練明細；指向 Supabase 或 live 頁即可。
  • 唔 force-push。唔寫入 Supabase 公開表 hx_test。唔寫秘密／.env／token。

5. 日常改版流程

  • 先讀交接日誌，再 pull／對齊。
  • 改 HTML：右下角 version 必改（細 +0.1，大 +1.0）。hx.html 側欄 ?v= 跟住加。
  • 改完：講 version；用戶自己 refresh 已開 tab。唔好開新 browser／Chrome。
  • 應上線嘅改動：更新 Vercel／Supabase；交接日誌寫重點；commit + push（令 Vercel 同屋企機都收到）。唔 push 秘密。唔 force。唔 skip hooks（除非用戶叫）。
  • 暗號 bye／收工：即刻處理未同步事項、寫交接、push。Status／共用資料以 Supabase 為準，唔好只留本機。
  • 新規則寫入呢頁，並更新本地 rule。唔可以只寫本地。
  • SharePoint 連結只解 %；唔用第三方短網址。
  • 細主題標題用相近但唔同色，方便分隔。
